# Source control

## Source control

The Git tab follows VS Code's Source Control view, with the colours taken from VS Code itself (the git extension's file status colours, the Dark and Light Modern gutter colours, the diff editor's line and word backgrounds). Everything runs through the `git` command line; nothing is reimplemented.

- A badge on the GIT rail tab shows how many files changed. The view shows the branch with ahead and behind counts, a summary (modified, added, deleted, untracked), a commit box and button (Ctrl+Enter commits; with nothing staged it stages everything first), **Staged Changes** and **Changes** with a count each, and per file a coloured status letter (M, A, D, U, !). Hover a row for open file and stage / unstage buttons; the + and - on a section header stage or unstage everything.
- **GRAPH** draws the history of HEAD, every local branch and the remotes in lanes (the first five are drawn; merges are hollow dots), with branch and tag labels. Click a commit to see its files, click a file for its diff. Ctrl+click marks a commit, Shift+click another one lists the files that differ between the two (the marked one on the left).
- **TIMELINE** lists the commits that touched the file in the active tab. Click one for that file's diff against its parent, or Ctrl+click one revision and Shift+click another to compare the two.
- Diff tabs show side by side when the editor is 900 px or wider and inline below that (button or `i` to switch), word level highlights inside changed lines, hatched filler where a side has no line, and unchanged stretches folded (click a fold, `e` expands all). F7 / Shift+F7 or the arrow buttons jump between changes; the scrollbar marks them. Enter or Open File opens the real file.
- In the editor, bars next to the line numbers mark lines added (green), changed (blue) and removed (a red wedge) against HEAD; click one to peek at the change: a panel under the lines shows the HEAD lines in red and yours in green, with buttons to revert the change in the buffer (Ctrl+Z undoes it), open the full diff, and step to the previous or next change (Esc or the X closes it). Rest the pointer on a line number, or on the faint blame text after the cursor line, for a tooltip with the commit message, author, age and hash. The status bar shows who last changed the cursor line and when (click it for that commit's diff), and the same text is shown faintly after the line.

Acting on changes works like VS Code. The **...** menu has Pull, Push, Fetch, Sync, Checkout to..., and submenus for Commit (Amend, Signed Off, Commit and Push, Undo Last Commit), Changes (Stage, Unstage or Discard All), Branch (Merge, Create, Create From, Rename, Delete, Publish), Stash and Tags, plus View as Tree or List. The arrow on the Commit button opens the same commit variants; with nothing to commit the button becomes **Sync Changes** or **Publish Branch**. Committing with nothing staged asks whether to stage everything (Yes, Always, Never). **Discard Changes** (the undo button on a row or on the Changes header, or right-click) asks first, in VS Code's words: "Are you sure you want to discard changes in 'x'?", "Are you sure you want to DELETE 'x'?" for an untracked file, and for several files "Are you sure you want to discard ALL changes in N files?" with **Discard All N Files**, **Discard Tracked Changes** and Cancel. The Pull submenu has Pull, Pull (Rebase) and Pull from..., Push has Push and Push to..., the Branch submenu has Rebase Branch..., and the Remote submenu adds or removes remotes and fetches from all of them. While a merge, rebase, cherry-pick or revert is unfinished, the view shows a banner with Continue, Skip (rebase and cherry-pick) and Abort. Files with conflicts get their own **Merge Changes** section (click one to open it, the + stages it as resolved). Click a conflicted file in Merge Changes for the **merge editor**: the two sides (Incoming left, Current right) on top with the unchanged lines folded, a Result pane below that updates as you choose, and per conflict Accept Current, Incoming, Both or Base (diff3 style files), Reset, plus All Current / All Incoming and previous / next conflict (F7). **Complete Merge** writes the result and stages the file; Open File gives the plain editor with the markers. In the plain file, the conflict blocks are tinted (current green, incoming blue) and the `<<<<<<<` line carries **Accept Current**, **Accept Incoming** and **Accept Both**; each is one undo step. Checking out a branch that would overwrite local changes offers Stash & Checkout or Force Checkout. Push, pull and fetch run in the background. In a diff tab, **Stage Change**, **Unstage Change** and **Revert Change** act on the current change (F7 to pick it). Hovering a change in a diff tab shows the same buttons (stage and revert, or unstage) on its first row, so you can act on it without selecting it first. Right-click a file, a commit, a section or a tab for context menus.

## Password prompts

git and ssh ask for credentials through a dialog inside the editor instead of a terminal: HTTPS user names and passwords or tokens, ssh key passphrases, and "trust this host key?" questions. The secret goes from the dialog to git or ssh through a private unix socket and is never written to disk or put on a command line. Whether git remembers it is up to your git credential helper.
